- 2026-10-23 21:30: Prompts v1 added: `prompts/describer.v1.md` (the trained task), `builder.v1.md`, `critic.v1.md`, `lessons.v1.md`. All per-call data (screenshot, previous spec, fixes, house lessons) goes in the user message, so each role stays one Mubit task. Freeze the Describer before the overnight run. Why: a changed system prompt or model starts a new task.
- 2026-10-23 21:30: Mubit session per site (`metadata.user_id = site-<slug>`). Why: Mubit holds back test cases by session, so one site's rounds never leak between training and testing.
- 2026-10-23 22:30: Second loop, `--mode dom`: the Describer reads `measure.json` as compact text (`prompts/describer-dom.v1.md`, its own Mubit task) and the fixes come from a code diff of original vs rebuild measurements (`src/dom-diff.ts`), not an LLM Critic. Why: text-only, so it trains even if Mubit can't train on images; cheaper; and deterministic. Inputs are about 700 tokens median, 2,200 max. Each mode keeps its own lessons file.
- 2026-10-23 23:30: Overnight plan while there is no Mubit key: scale capture to about 250 sites; label each with `data/taxonomy.md` (code features in `data/features.json`, visual labels from Haiku agents viewing screenshots); write Describer v2 and per-layout playbooks; batch runner (`npm run batch`) starts once a key exists. Why: nothing in the product can run without Mubit, so get everything else ready. The labels and prompt drafting are dev tooling by our coding agents, not product LLM calls; no product prompt was run outside Mubit.
- 2026-10-23 23:30: Lessons now per mode and per layout style (`data/lessons/<mode>/<layout>.md`, plus `_all.md`), and `--learn` runs layouts in parallel and sites within a layout in order. Why: advice for a poster hero is not advice for a card grid, and one queue of 250 sites is too slow overnight.
- 2026-10-23 23:30: Batch budget defaults to 5,000 LLM calls (`BATCH_MAX_CALLS`), up to 4 epochs, stopping early if holdout first-shot gains under 1 point twice. Why: a hard cap on spend while nobody is watching.
- 2026-10-24 00:30: Prompts v2 are the default (`DESCRIBER_PROMPT`/`BUILDER_PROMPT`, v1 kept for comparison): Describer image and DOM, Builder, 9 layout playbooks, from `prompts/v2` (see `prompts/CHANGES-v2.md`). New spec grammar (CANVAS, FONTS, SHAPES, MEDIA, TEXT with exact x,y and " | " line breaks) and a fixed fit script, which the code now adds itself if the Builder leaves it out. The Describer's user message is headed PLAYBOOK (picked by `layout_style` from `data/labels.json`) and HOUSE LESSONS. Freeze these before the first recorded call: a changed prompt is a new Mubit task. Why: hand-written v2 specs, built literally, scored 89.2 (aardvark-book-club, image) and 72.1 (kern-society, DOM). These are reference ceilings, not model outputs.
- 2026-10-24 01:30: Scoring fix: when masks hide most of the frame (full-screen canvas), the pixel score compared grey with grey and gave 100 to any rebuild. `score()` now reports `visible`. In image mode the total is scaled by it below 30%; in DOM mode the total blends in a measurement score (`domScore`: text found, position, size, colour, page colour), and uses it alone below 30% visible. Why: otherwise the DOM loop would "converge" on round 1 on most Awwwards heroes.
- 2026-10-24 01:30: Extra holdout (`data/holdout-extra.json`, 15 type-led train sites spread by jury score), treated as holdout in both modes and never recorded. Why: only 3 of the 20 main holdout heroes are pixel-friendly, too few for a screenshot scorecard. Two main holdout sites were swapped by the capture agent after failing the loader recheck (see PR #3), and la-revoltosa is flagged as a bad capture, so the main holdout is 19 usable sites.
- 2026-10-24 01:30: Labels for all 250 sites (`data/labels.json`), 28 flagged `bad_capture` and skipped. Big layouts learn in sub-queues of about 12, with lesson updates queued per layout. Train runs at concurrency 8 per mode.
- 2026-10-24 09:00: Local training loop while there is no Mubit key (Luka's call): `LLM_BACKEND=local` sends calls to a model on this laptop (mlx-lm, `mlx-community/Qwen3-4B-Instruct-2507-4bit`, OpenAI-compatible server at `LOCAL_LLM_URL`), DOM mode only (text). No provider is called and Mubit sees nothing, so this is the one exception to "every LLM call through Mubit", for offline dev only; Mubit stays the default. Local runs are tagged `local-*`, carry `backend: "local"` in `run.json`, keep their own lessons (`data/lessons/local-dom/`) and never count against the Mubit batch budget. Why: we can build and measure the whole learn-and-evaluate loop now and swap in Mubit when the key arrives.
- 2026-10-24 09:00: Code Builder (`src/compile.ts`, `BUILDER=code`, the default on the local backend): compiles a v2 spec to HTML with no LLM. Why: the Builder is meant to be fixed; in code it is exactly fixed, free and instant, so every score change comes from the Describer.
- 2026-10-24 09:00: Rule-based teacher (`src/teacher.ts`): writes a v2 spec from `measure.json` in code, following `describer-dom.v2.md`. Its train specs are the first fine-tuning targets; the model's own best rounds replace them when they score higher (expert iteration). Holdout specs are only scored, never trained on. Caveat: the DOM score compares measurements, so a rule-based transcriber scores high on it by construction; the pixel half of the score is the honest check.
- 2026-10-24 09:30: Describer reply limit raised from 900 to 1,600 tokens (both modes, both backends). Why: specs are mostly numbers, which tokenise at about 1.6 characters a token, so a 400-word spec runs past 1,000 tokens and was being cut off. A reply limit is not part of a Mubit task's identity, so the task is unchanged.
