- 2026-10-23 21:30: Mubit session per site (`metadata.user_id = site-<slug>`). Why: Mubit holds back test cases by session, so one site's rounds never leak between training and testing.
- 2026-10-23 22:30: Second loop, `--mode dom`: the Describer reads `measure.json` as compact text (`prompts/describer-dom.v1.md`, its own Mubit task) and the fixes come from a code diff of original vs rebuild measurements (`src/dom-diff.ts`), not an LLM Critic. Why: text-only, so it trains even if Mubit can't train on images; cheaper; and deterministic. Inputs are about 700 tokens median, 2,200 max. Each mode keeps its own lessons file.
- 2026-10-23 23:30: Overnight plan while there is no Mubit key: scale capture to about 250 sites; label each with `data/taxonomy.md` (code features in `data/features.json`, visual labels from Haiku agents viewing screenshots); write Describer v2 and per-layout playbooks; batch runner (`npm run batch`) starts once a key exists. Why: nothing in the product can run without Mubit, so get everything else ready. The labels and prompt drafting are dev tooling by our coding agents, not product LLM calls; no product prompt was run outside Mubit.
- 2026-10-23 23:30: Lessons now per mode and per layout style (`data/lessons/<mode>/<layout>.md`, plus `_all.md`), and `--learn` runs layouts in parallel and sites within a layout in order. Why: advice for a poster hero is not advice for a card grid, and one queue of 250 sites is too slow overnight.
- 2026-10-23 23:30: Batch budget defaults to 5,000 LLM calls (`BATCH_MAX_CALLS`), up to 4 epochs, stopping early if holdout first-shot gains under 1 point twice. Why: a hard cap on spend while nobody is watching.
